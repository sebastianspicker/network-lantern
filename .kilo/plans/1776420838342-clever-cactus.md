# Remediation Plan: network-diagnostics-suite audit findings

## Objective

Resolve all confirmed audit findings iteratively, with test-first changes, minimal surface area per step, and explicit verification after each iteration.

## Assumptions

- No backward-compatibility guarantee is required for undocumented broken behavior.
- The conservative Windows tuning surface is the intended long-term public contract; legacy broad tuning APIs should no longer be first-class unless needed only for migration.
- Repo policy prefers surgical fixes with regression coverage before behavior changes.
- Verification must include existing CI-equivalent checks plus targeted surface probes for the changed entrypoints.

## Success criteria

1. `Invoke-NetworkDiagnostics.ps1` launches downstream workflows with correct argument binding for defaults and explicit multi-value overrides.
2. Throughput saved profiles apply with the documented precedence: defaults < config/profile < explicit CLI arguments.
3. Windows tuning public exports match the repo's conservative documented scope.
4. Windows tuning restore is made safer and verify mode does not report false success on unsupported or unverified platforms.
5. Path diagnostics status modeling distinguishes skipped work from successful work and reports failures based on broader diagnostic outcomes than only TCP/443.
6. Bash path defaults become operator-safe without leaving tests or docs in a contradictory state.
7. Docs, tests, naming, and CI coverage align with the corrected behavior.
8. Final verification passes and includes targeted surface probes. End state should be `VERDICT: PASS`.

## Constraints and guardrails

- Use the smallest correct changes.
- Do not mix unrelated fixes in one iteration.
- Add regression tests before changing behavior where practical.
- Avoid destructive tuning behavior changes without adding restore/verify coverage first.
- Preserve user changes in dirty worktrees.

## Implementation strategy

## Phase 1: Fix the top-level blocker first

### Iteration 1: Orchestration argument binding

Goal:
- Make `Invoke-NetworkDiagnostics.ps1` reliably pass arrays and switches to downstream scripts.

Changes:
- Add direct tests for the orchestration wrapper covering:
  - `-Workflow Triage -DryRun` default behavior.
  - explicit `-HostsIPv4`, `-HostsIPv6`, `-Protocols`, `-Rounds` values.
  - `Baseline` path + throughput composition.
- Refactor wrapper invocation so PowerShell-to-PowerShell calls preserve arrays correctly.
  - Preferred approach: invoke downstream script files directly within PowerShell rather than spawning `pwsh` for local script-to-script calls.
  - Preserve explicit isolation only if truly required; if isolation is needed, serialize complex args intentionally rather than relying on native argv binding.
- Verify `OutRoot`, `DryRun`, and `Quiet` still flow correctly.

Verification:
- Targeted Pester tests for orchestration.
- `pwsh -File ./Invoke-NetworkDiagnostics.ps1 -Workflow Triage -DryRun`
- `pwsh -File ./Invoke-NetworkDiagnostics.ps1 -Workflow Baseline -IperfTarget iperf3.example.net -DryRun`

Exit condition:
- No more `IPv4 hosts: IPv6` style corruption.

## Phase 2: Repair correctness issues with low migration risk

### Iteration 2: Throughput profile precedence and exit-code handling

Goal:
- Restore documented precedence and structured error behavior.

Changes:
- Add regression tests proving:
  - saved profile values load through the CLI wrapper,
  - explicit CLI args override saved profile values,
  - config values override defaults but not explicit CLI,
  - wrapper bootstrap/import failures return documented exit codes.
- Simplify precedence ownership so there is one effective merge authority.
  - Preferred approach: keep defaults in the module, let the CLI only pass user-intended bound parameters plus config/profile path selectors.
  - Alternative only if necessary: maintain wrapper merge logic but stop sending default-filled keys downstream.
- Move/import wrap module/path bootstrap in structured try/catch so import-time failures map to prerequisite/internal exit codes consistently.

Verification:
- Throughput Pester suite additions.
- `pwsh -File ./apps/throughput/iPerf3Test.ps1 -ProfileName <fixture> -WhatIf`
- Negative bootstrap test or controlled failing import-path test.

Exit condition:
- CLI profile loading behaves as documented and tests enforce it.

### Iteration 3: Windows tuning verify truthfulness and warning hygiene

Goal:
- Eliminate false success during verify and fix misleading diagnostics.

Changes:
- Add tests for verify mode when QoS enumeration is unavailable.
- Decide and implement verify semantics for unsupported/unverifiable environments:
  - If data required for verification cannot be obtained, `Success` must be false and component status must be `Warn` or `Unknown`, not `OK`.
- Fix the broken app-policy warning format string.
- Tighten verify component states so `Skipped` is not used where the requested verification actually failed.

Verification:
- Windows tuning Pester tests.
- `Optimize-NetworkPath.ps1 -Action Verify -DryRun -PassThru` on non-Windows should no longer claim success if policy enumeration failed.

Exit condition:
- Verify output reflects reality under unsupported or partial-verification conditions.

## Phase 3: Make destructive tuning behavior safer

### Iteration 4: QoS restore safety

Goal:
- Prevent restore from leaving the system in a worse state on partial failure.

Changes:
- Add tests around restore behavior for partial QoS recreation failure.
- Refactor restore flow to avoid delete-first semantics where possible.
  - Preferred approach: validate backup contents first, stage recreation safely, then reconcile managed policies.
  - If `NetQosPolicy` limitations prevent true transactionality, implement best-effort non-destructive reconciliation:
    - compute diff,
    - create/update needed policies first where possible,
    - remove stale managed policies last,
    - preserve prior managed state on partial failure.
- Strengthen restore result reporting to identify partial recovery explicitly.

Verification:
- Pester tests for successful restore, partial restore, and malformed backup inputs.

Exit condition:
- Managed policies are not eagerly destroyed before restore viability is known.

### Iteration 5: Reset scope ownership and backup manifest hardening

Goal:
- Restrict reset to settings owned by this tool and strengthen restore compatibility checks.

Changes:
- Add tests proving reset does not delete unrelated MMCSS task keys/values.
- Replace whole-key deletion with owned-value cleanup only.
- Enrich backup manifest with compatibility metadata such as:
  - machine name,
  - OS/platform/build where obtainable,
  - module version,
  - backup schema version,
  - NIC identifiers if relevant.
- Add restore-time validation rules for manifest compatibility, with a clear override policy only if already supported/documented.

Verification:
- Windows tuning Pester tests for manifest validation and reset ownership boundaries.

Exit condition:
- Reset only removes owned settings, and restore can reject obviously incompatible backups.

## Phase 4: Repair path-domain correctness semantics

### Iteration 6: Distinguish skipped work from successful work

Goal:
- Represent skipped pathping explicitly and stop reporting it as success.

Changes:
- Add tests for `-SkipPathping` result representation.
- Change path result model so skipped stages are expressible without overloading `Ok = true`.
  - Preferred approach: add explicit status fields, e.g. `PathpingStatus = OK|Fail|Skipped`, while keeping existing booleans only if needed for compatibility.
  - If keeping booleans, `PathpingOk` must be false or null when skipped; docs/tests must define that clearly.
- Update JSON/CSV serialization and any summaries accordingly.

Verification:
- Path Pester tests for dry-run and result serialization.

Exit condition:
- Consumers can distinguish skipped from successful pathping.

### Iteration 7: Broaden path pass/fail semantics

Goal:
- Stop using only `Tcp443OK` as the effective health signal.

Changes:
- Define a minimal but accurate result policy for path workflow completion.
  - Recommended model:
    - per-stage status fields for ping, tracert, pathping, tcp443, and port probes,
    - overall run status derived from critical stage outcomes,
    - process exit code fails when critical diagnostic stages fail, not only TCP/443.
- Add tests for mixed-result scenarios.
- Update summaries so console output reflects the broader status model.

Verification:
- Pester tests for mixed failures.
- Surface probe with mocked failing stages where practical.

Exit condition:
- Path diagnostics exit status aligns with actual diagnostic failure states.

### Iteration 8: Reduce hidden ambient state in PowerShell path helpers

Goal:
- Make path helpers easier to test and safer to refactor.

Changes:
- Incrementally pass execution settings explicitly into helpers that currently depend on ambient variables.
- Prioritize helpers whose behavior directly affects execution or status reporting:
  - `Invoke-HostDiagnostics`
  - `Get-RoundDefinitions`
  - related arg builders if needed
- Keep the refactor local; do not redesign the whole subsystem.

Verification:
- Existing path tests plus new unit tests for helpers with explicit inputs.

Exit condition:
- Critical helpers no longer depend on caller-scope variables for core behavior.

## Phase 5: Make the Bash path workflow operator-safe

### Iteration 9: Safe defaults and selector validation

Goal:
- Prevent accidental huge runs and reject ambiguous empty selectors.

Changes:
- Add Bats coverage for:
  - empty `--types`, `--rounds`, `--hosts4`, `--hosts6` rejection,
  - reduced default dry-run count,
  - explicit full-matrix invocation if such a mode is introduced.
- Change CLI behavior so empty-string selectors are input errors, not silent fallbacks.
- Reduce default run scope to an operator-safe baseline.
  - Preferred approach: fewer rounds and/or fewer test types by default, while keeping explicit selectors for full coverage.
  - If needed, add an explicit `--full-matrix` style opt-in rather than keeping the current default.
- Reconcile docs and tests with the new default plan size.

Verification:
- Bats suite.
- Dry-run smoke command.

Exit condition:
- Default Bash path execution is bounded and empty selectors are rejected.

## Phase 6: Finish throughput and GUI correctness

### Iteration 10: Throughput validation hardening and GUI cancellation

Goal:
- Close remaining throughput correctness gaps after precedence is fixed.

Changes:
- Add tests for IPv6 validation edge cases including invalid compressed forms and scoped/link-local addresses if intended to be supported.
- Replace the permissive fallback IPv6 acceptance with a stricter validator.
  - Preferred approach: use platform parsing APIs where they correctly validate literal IP addresses, then separately permit hostnames.
- Add GUI validation for advanced fields before launch.
- Fix child process tracking/cancellation in the GUI job model.
  - Ensure spawned process identity is captured and terminated reliably on cancel.
- Align GUI non-Windows/prerequisite exit behavior with canonical exit codes where applicable.

Verification:
- Throughput Pester tests.
- Manual GUI smoke if feasible in environment; otherwise unit-level job/cancel tests and clear residual note.

Exit condition:
- Throughput validation is stricter and GUI cancel does not leave orphaned `iperf3` processes by design.

### Iteration 11: `Compare-Iperf3Runs` behavior/doc alignment

Goal:
- Make regression comparison either do what it claims or document its limited scope accurately.

Changes:
- Add tests that define the intended comparison output.
- Either:
  - implement actual aggregate throughput delta fields, or
  - narrow the help text to reflect status/count/time-only comparison.
- Prefer implementing the missing delta fields if summary data already supports it with minimal code.

Verification:
- Throughput Pester tests around comparison output.

Exit condition:
- Public docs and behavior match.

## Phase 7: Public surface, naming, and documentation alignment

- Replace or remove the failing GUI stub from the app surface.

Verification:

Exit condition:

### Iteration 13: Path naming cleanup

Changes:

## Autonomous execution notes

- Execute iterations in order unless a lower-numbered iteration is blocked by an uncovered prerequisite.
- After each iteration:
  - run only the smallest relevant tests first,
  - fix any failures introduced by that iteration,
  - then rerun broader verification before moving on.
- Keep commits, if requested later, aligned to iteration boundaries where possible.
- If a legacy export removal risks external breakage discovered during implementation, downgrade that step to explicit deprecation plus doc removal and note the residual risk.
